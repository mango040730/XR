# 셰이더 그래픽 · 무작위 낚시 · 이동 끊김 개선

작업일: 2026-11-08 (Asia/Seoul). 작업 중 프로젝트가 `낚시터`에서 `공간 실험` 폴더로 이동되었습니다. 변경한 소스는 이동된 폴더에 보존되어 있습니다. 원래 VR 서비스 폴더는 수정하지 않았습니다.

## 변경한 동작

- 낚시터에 ACES 필름 톤, 따뜻한 주광과 차가운 환경광, 2048px 부드러운 방향광 그림자, 약한 발광 번짐을 연결했습니다. 그림자는 장면과 인물 표시 상태가 바뀔 때만 갱신합니다.
- 수면은 GPU 버텍스/노멀 셰이더로 작은 파동을 계산합니다. 시점에 따라 변하는 프레넬 색상과 6개 등 위치의 반사 하이라이트, 수조 바닥의 움직이는 빛무늬를 추가했습니다. 반사 하이라이트는 수식 기반이며 실제 장면을 다시 그리는 평면 반사나 화면 공간 반사가 아닙니다.
- 모바일의 좁은 화면과 몰입형 VR에서는 후처리 패스를 생략합니다. 안내의 가벼운 그래픽을 켜면 수면 세부 파동과 발광 후처리를 줄이고 DPR을 1로 낮춥니다. 기본 DPR 상한은 1.5입니다.
- 찌를 투입할 때마다 60~300초에서 균등하게 무작위 대기 시간을 선택합니다. 시간이 되면 자동으로 한 마리를 잡고, 물고기의 짧은 점프·이름/길이·누적 마릿수를 알립니다. 버튼/F로 다시 투입할 수 있습니다. 회수·일어남·자리 변경·퇴장 시 대기를 취소합니다. 프레임에서 기한을 검사하므로 해제되지 않은 타이머가 쌓이지 않습니다.

## WASD/시점 끊김 검토

사용자가 확인한 증상은 다른 월드 입장이 아니라 걷거나 시점을 돌릴 때였습니다. 기존 선택 검사는 매 프레임 20m 범위의 전체 월드 메시를 검사했습니다. 빈 곳을 바라봐도 건축·바닥·장비를 모두 검사했습니다.

수정 후에는 3m 이내의 상호작용 메시를 먼저 검사합니다. 선택 후보가 있을 때에만 그 후보까지의 짧은 구간에서 벽에 가리는지 검사합니다. VR의 컨트롤러/머리 사이 가림 검사와 충돌은 유지했습니다. 정적 병합 메시의 행렬 재계산을 줄였으며, 수면 버퍼를 매 프레임 CPU에서 수정·전송하던 경로를 GPU uniform 갱신으로 바꿨습니다. 새 월드의 모든 재질과 숨긴 좌석 패널은 입장 전에 compileAsync로 준비하고 텍스처를 올립니다. 준비 취소·실패 시 기존 월드를 보존합니다.

CPU 측정 환경은 macOS arm64 / Node v26.13.0이며, 실제 낚시터 Three.js 메시를 이용한 빈 공간 시점 검사 240회입니다. 기록된 평균은 기존 약 0.634ms, 개선 후 약 0.076ms로 약 8.3배 감소했습니다. 실행할 때마다 수치는 달라집니다. `test-results/interaction-profile.json`에 최신 측정 환경과 수치를 저장합니다. 이 결과는 선택 검사 한 항목의 Node CPU 비용이며 전체 프레임 시간이나 브라우저/헤드셋 FPS가 아닙니다.

- `src/engine/rendering/Renderer.ts`, `profile.ts`: 톤·후처리·픽셀 비율·그림자 갱신·재질 준비
- `src/engine/world/types.ts`, `createWorld.ts`, `WorldManager.ts`, `src/engine/core/Engine.ts`: 월드별 렌더 설정과 준비 수명주기
- `src/engine/interaction/InteractionSystem.ts`: 가까운 선택 후보 우선 검사
- `src/worlds/indoor-fishing/waterShaders.ts`, `water.ts`: 수면·바닥 셰이더, 물고기 잡힘 시각 피드백
- `state.ts`, `runtime.ts`, `equipment.ts`, `config.ts`, `geometry.ts`: 1~5분 기한과 취소, 찌 반응, 품질 설정, 정적 변환
- `src/ui/FishingHUD.ts`: 낚시 안내·결과·재투입·그래픽 품질
- `tests/fishing.test.ts`, `interaction.test.ts`, `world-manager.test.ts`, `interaction-performance.test.ts`, `tests/e2e/fishing.spec.ts`: 경계 시각·취소·레이 검사·준비 취소·CPU 측정·브라우저 시나리오

## 검증과 남은 제한

최종 `npm run check`(린트 → 테스트 → 기존 GLB → 타입/프로덕션 빌드/개발 진단 분리)가 통과했습니다. 13개 테스트 파일의 80개 테스트가 통과했습니다. 60초 이전 포획 방지, 300초 경계, 중복 포획 방지, 매 투입 새 대기 시간, 회수/자리 변경/일어남/퇴장 취소를 가상 시계로 확인했습니다. 실제 메시를 대상으로 한 선택·가림·충돌·자원 해제 검사도 통과했습니다.

브라우저 E2E는 로컬 소켓 제한 후 확장 실행이 승인되지 않아 실행하지 못했습니다. 따라서 새 셰이더의 실제 GPU 컴파일·시각 품질·WASD 체감·전체 FPS·스크린샷과 헤드셋은 미검증입니다. 구현 및 Node 검사와 실기기 검증을 구분합니다. Three.js 번들 500KB 경고는 유지됩니다.

## 실행

`공간 실험` 폴더에서:

```sh
npm run dev -- --port 5173
```

`http://127.0.0.1:5173/?fishing` 접속. `?` 안내에서 전체 구도/반대편/가벼운 그래픽을 선택할 수 있습니다. 기존 서비스의 혼자 활동해요와 `/?lab=1` 등록도 유지합니다.

최종 검사: `npm run check`. 브라우저 실행 가능 환경에서는 `npm run test:e2e -- --project=chromium fishing.spec.ts`로 화면/입력/포획을 확인합니다. E2E 포획 검사는 브라우저 가상 시계를 사용하며 실제 대기 시간을 단축하는 개발용 전역 명령을 제품에 추가하지 않았습니다.
