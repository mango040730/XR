# 전체 공간의 베벨 세그먼트 2

2026-11-08 (Asia/Seoul).

사용자의 “Blender 용어인 세그먼트 2”는 베벨 기준으로 해석했습니다. 모서리의 90° 구간에 두 개의 면이 생기는 0° → 45° → 90° 단면을 코드 지오메트리로 구성했습니다. 넓은 원래 면을 전체 분할하는 방식이 아니라 가장자리의 단면만 나눴습니다. [Blender Bevel 공식 설명](https://docs.blender.org/manual/en/4.4/modeling/modifiers/generate/bevel.html).

## 적용

`src/worlds/indoor-fishing/bevel.ts`의 `BEVEL`을 한 곳에서 관리합니다.

- `segments: 2`
- `maxWidth: 0.015` (1유닛=1m이므로 최대 1.5cm)
- `widthRatio: 0.12` (가는 부재는 최단변의 12%까지만)

기둥·천장 보·창틀·벽·바닥 부재·수조·나무 의자·선반·도구함·3D 조작 패널과 아바타의 사각 부재까지 공통 Kit의 사각 메시/각진 보에 적용합니다. 이번 장면에서 1,024개 부재, 치수별 공유 지오메트리 81종입니다. 둥근 원통/찌/머리/나무 원뿔, 두께가 없는 물/파문/낚싯줄/글자 평면에는 사각형용 베벨을 넣지 않았습니다. 기존 로우폴리 곡면과 수면 셰이더가 유지됩니다.

실제 웹 공간의 생성 메시를 바꿨습니다. `Downloads/낚시터.blend` 같은 별도의 원본 Blender 파일을 수정하거나 원본 파일의 Modifier를 설정한 결과로 보고하지 않습니다.

외곽 크기를 키우지 않고 원래 범위 안으로 모서리를 깎습니다. 따라서 기존 좌석 위치, 이동 충돌, 창틀-벽 깊이 간격과 수조 크기를 유지합니다. 정적 메시 병합과 치수별 공유를 유지하며, 병합 중에는 캐시 지오메트리를 성급하게 dispose하지 않고 장면 준비 종료 시 사용하지 않는 캐시만 정리합니다. 살아 있는 공유 지오메트리는 월드 퇴장 때 기존 disposeObject가 정리합니다.

## 검사

`npm run check`에서 린트 → 15개 파일/86개 테스트 → 기존 GLB 검증 → 타입/프로덕션 빌드/개발 진단 분리가 통과했습니다.

추가 `tests/bevel.test.ts`는 다음을 검사합니다.

- 한 모서리의 0°/45°/90° 단면과 닫힌 메시(각 변에 정확히 두 면 연결)
- 바깥을 향하는 모든 면과 92삼각형/부재
- 큰 기둥과 얇은 부재의 원래 크기 유지
- 반복 부재의 지오메트리 공유와 병합 후 캐시 정리

이전 `tests/surfaces.test.ts`의 바닥 겹침/창틀 깊이/간판 앞면 검사도 통과했습니다. 전체 메시 삼각형 수는 숨긴 좌석 패널 등까지 포함해 102,398개입니다. 이 수치는 실제 렌더 호출이나 GPU FPS가 아닙니다. Node CPU 측정에서 빈 곳을 보는 최적화된 선택 검사 경로는 약 0.08ms였으며, 브라우저/헤드셋 시각 결과와 실제 프레임 속도는 미검증입니다.

주요 변경: `bevel.ts`, `geometry.ts`, `runtime.ts`, `tests/bevel.test.ts`, `tests/interaction-performance.test.ts`.
