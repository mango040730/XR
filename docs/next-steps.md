3. **최종 아바타**: 임시 capsule/구체를 GLB + 애니메이션으로 교체하고 프로필 avatar ID를 자산 목록과 연결합니다. 현재는 임시 외형 색상 선택입니다.

5. **멀티플레이/음성**: 접속자·동기화·서버 권위 이동·프라이버시 요구를 정하고 별도 구현합니다. 현재 서버 인원과 친구는 데모이며 실시간 처리는 없습니다.
6. **디자인 후속 조정**: [원본 비교](design-audit.md)에서 남은 glass/폰트 래스터화와 Canvas 텍스트 차이를 검토합니다. React 전환은 필요할 때 Signal/Store 경계 위에서 진행합니다.

# 다음 개발 단계

3단계에서 공통 PC·VR 입력/이동/텔레포트/선택을 코드로 연결했습니다. 코드 구현과 실제 장치 검증을 구분하며 아래 순서로 진행합니다.

## 1. 실제 VR 기기 검증과 정책 조정

[실기기 체크리스트](vr-device-checklist.md)를 A/B/GLB에서 수행합니다. 지원/권한, 양안, local-floor, 컨트롤러 매핑, 텔레포트/30도 snap, 추적 손실/리센터, 가상 몸 제한·rig 보정/암전, 종료/재진입을 확인합니다. 특히 물리적인 머리 이동을 보정하는 정책의 불편함·드리프트와 UI 가독성을 측정합니다. 문제를 먼저 해결한 뒤 연속 이동/회전의 속도와 편의 설정을 조정합니다. 아직 실제 하드웨어를 통과한 상태가 아닙니다.

## 2. 최종 Blender 자산 연결

[Blender 규격](blender-workflow.md)에 따라 별도 GLB/config/registry를 추가합니다. 실제 단위·방향·텍스처·재질·시작 위치와 수동 AABB/텔레포트 영역을 검증합니다. 이름 기반 interactions를 문/버튼/소품에 연결하고 필요한 콘텐츠 동작을 action 구독으로 구현합니다. 현재 문 애니메이션/아바타는 없습니다.

## 3. 요구가 생길 때 확장

- 실제 계단/경사면이 확정되면 capsule/triangle collision 또는 collision.glb 어댑터를 검토합니다. 평면/AABB 구현을 임의로 대체하지 않습니다.
- 기기 매핑이 xr-standard가 아니거나 touchpad-only인 경우 공식 input profiles 기반 지원을 별도로 검토합니다. 현재 레이 선택만 허용하고 스틱을 추측하지 않습니다.
- 포물선 텔레포트, 컨트롤러 모델, 접근 가능한 VR 내부 메뉴/월드 전환 UI는 장치 검사 결과를 보고 추가합니다.
- 대형 자산의 요청 취소·시간 제한·최대 메모리·폴리곤/텍스처 예산, 물리 GPU 성능도 별도 검증합니다.

## 이후 별도 범위

Figma 최종 React UI·Blender 최종 공간/아바타·계정·초대 기반 마이룸·멀티플레이·음성·DB는 공통 엔진/장치 검증 후 요구사항을 정합니다. 현재 추가하지 않았습니다. 기존 보안/번들 경고는 호환 업데이트를 확인하며 기능과 무관한 강제 메이저 변경은 하지 않습니다.
