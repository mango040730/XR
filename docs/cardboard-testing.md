# 스마트폰 VR 박스 수동 검증

## 접속 준비

1. PC에서는 프로젝트 폴더에서 `npm run dev`를 실행하고 출력된 localhost 주소로 전체 서비스 흐름을 확인합니다. 기존 엔진 실험 메뉴는 주소 뒤 `?lab=1`입니다.
2. 스마트폰 센서는 보안 컨텍스트가 필요합니다. **PC의 127.0.0.1 주소는 휴대폰에서 PC를 가리키지 않습니다.** 같은 Wi-Fi 접속과 휴대폰이 신뢰하는 HTTPS 주소가 필요합니다.
3. 단순 화면/터치 UI 확인은 `npm run dev -- --host 0.0.0.0` 후 PC의 로컬 IP와 출력 포트로 접근할 수 있습니다. 이 HTTP 주소에서 센서 기능이 되는 것으로 판단하지 마세요. 외부 공개는 수행하지 않았습니다.
4. 센서 실험은 기존 신뢰된 HTTPS 개발 호스트나 별도 준비한 로컬 TLS reverse proxy를 사용하세요. 인증서를 신뢰할 수 있는 환경을 먼저 준비해야 합니다. 이번 작업에서 인증서 설치/배포/외부 터널은 수행하지 않았습니다.
5. 스마트폰에서 페이지를 열어 가로로 회전합니다. **VR 박스 모드 → 센서 허용 후 VR 시작**을 손으로 눌러 권한을 요청합니다. iPhone에서는 동작·방향 권한 대화상자를 허용합니다. 지원되는 브라우저에만 requestPermission 호출이 있습니다.
6. 거절되면 센서 안내에서 다시 요청하거나 **드래그 체험**을 선택합니다. 거절 후 재요청이 막히면 Safari/Chrome 사이트 권한을 확인합니다. 권한 허용이어도 센서 데이터가 오지 않으면 추적 성공으로 간주하지 않습니다.
7. 화면이 양안으로 바뀐 것을 확인한 뒤 박스에 넣습니다. 자동 전체화면/가로 잠금이 거절되면 브라우저 UI에서 직접 처리합니다. iOS의 전체화면/잠금 지원은 별도 확인 대상입니다.

## 확인 항목

- [ ] iPhone Safari / Android Chrome 각각 보안 연결과 권한 허용/거절/재시도
- [ ] orientation 실제 수신, 가로 좌우 방향과 yaw/pitch/roll, 화면 회전 후 축 보정
- [ ] 좌우 눈에 동일 UI 전체가 나타나며 중앙 잘림/겹침/과한 시차가 없는지
- [ ] 실제 박스 렌즈에서 글자·버튼을 읽을 수 있는지, 눈 간 거리/패널 거리 조정
- [ ] 로그인부터 약속 완료까지 시선 1.2초로 선택, 선택 후 시선을 떼면 재선택
- [ ] 빠른 머리 움직임·다른 버튼 통과 중 의도치 않은 선택/누적 dwell이 없는지
- [ ] 원본 별점/작은 시간 버튼이 시선으로 충분히 선택 가능한지
- [ ] VR 입력 필드의 데모 대체 문구가 동작하고 실제 키보드 입력과 혼동하지 않는지
- [ ] 시뮬레이션의 앞/뒤/30도 회전과 벽/장애물 충돌, 월드 오브젝트 시선 색 변경
- [ ] 홈 복귀/다른 모드에서 플레이어 시작 위치·입력·자원 정리
- [ ] 패널 정면 맞추기, UI의 VR 종료, 브라우저 뒤로/복귀, 재진입
- [ ] 5~10분 사용 시 프레임/발열/배터리/어지럼/읽기 피로
- [ ] 앱 전환·잠금·센서 중단·추적 재수신 때 방향 급변 여부

PC에서는 드래그로 시선을 조절하고 R로 정면 패널을 다시 배치하며 Esc로 Cardboard를 종료합니다. 실제 센서가 들어오면 드래그 대신 센서를 사용합니다. VR 박스 내 텍스트 필드는 준비된 데모 문구를 넣습니다. 실제 자유 입력은 박스 밖의 터치 키보드 또는 PC 키보드입니다.

현재는 일반 stereoscopic prototype입니다. 렌즈별 distortion/chromatic correction, QR viewer profile, 위치 추적, 자동 보행은 구현하지 않았습니다. 고정 IPD 64mm/패널 2.8m·폭 3m는 시작값이며 기기 검증을 통과한 값이 아닙니다. 표준 WebXR 헤드셋은 별도의 [기기 체크리스트](vr-device-checklist.md)를 수행해야 합니다.
