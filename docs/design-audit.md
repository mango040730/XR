## 신규 화면

아바타 선택, 시뮬레이션 로딩·HUD·일시정지, 채팅/빈 상태, 친구 초대/완료, 초대 수락·거절, 프로필·활동, 약속 목록·참여자 선택, 홈 복귀 확인, 공통 오류·복구, VR 박스 안내, 센서 권한 안내. 네트워크/모델/서버 오류는 공통 오류 화면을 사용합니다. 외부 서버 요청을 하지 않는 데모에 가짜 네트워크 성공 상태를 만들지 않았습니다.

`src/components/designSystem.ts`의 Button/Panel/Screen/Input/Row와 `src/ui/service.css` 토큰을 공유합니다. 13개 원본 컴포넌트는 `src/ui/figma/Frame1144_*.tsx`, 동작 연결은 `ServiceScreens.ts`에 있습니다. TSX는 React가 아닌 native DOM factory를 사용합니다. React나 Tailwind 런타임을 추가하지 않았습니다.

## 시각 비교 방법

`/?designReview=700`처럼 원본의 기본 콘텐츠만 보는 디자인 검토 모드가 있습니다. 일반 서비스와 같은 코드 컴포넌트/에셋/CSS를 사용하며 3D 배경 대신 원본 내보내기의 회색 배경을 사용합니다. 실제 입력 가능한 서비스 스크린샷은 별도로 저장합니다. 이 경로는 원본 기본 상태 비교용이며 서비스 E2E를 대신하지 않습니다.

```bash
npm run test:e2e
npm run compare:figma
```

비교 결과: `test-results/design-comparison/`의 `*-pair.png`(왼쪽 원본/오른쪽 구현), `*-difference.png`, `metrics.json`. 수치는 0~255 RGB 채널 평균 절대 오차와 최대 채널 차이 20 초과 픽셀 비율이며 유사도 인증/자동 합격 기준은 아닙니다. 브라우저/Figma의 글꼴 래스터화와 glass 광학 효과가 달라 완전한 픽셀 동일성을 주장하지 않습니다. 실제 비교 결과와 수정 내용은 progress.md에 기록합니다.

## PC와 VR 표현

PC는 1200×600 프레임을 가용 화면에 비례 축소하고 3D 공간 위에 표시합니다. 모바일의 작은 글자를 읽기 위해 가로 방향을 권장합니다. Cardboard에서는 같은 **실시간 DOM 요소의 배치·텍스트·로컬 이미지·선택 상태**를 CanvasTexture로 그린 3D 평면을 두 카메라로 렌더링합니다. 원본 화면 전체 이미지를 텍스처로 붙이지 않습니다. Canvas의 glass는 반투명/테두리 근사이고 PC의 backdrop-filter와 동일한 광학 효과는 아닙니다. 장소 지도는 원본 예시이며 선택한 데모 장소의 실제 좌표를 보여주는 지도 API가 아닙니다.

VR 폭/거리/IPD/dwell은 `src/experience/cardboardLogic.ts`의 설정입니다. 패널은 월드에 고정되어 머리를 돌려 버튼을 조준할 수 있습니다. 화면 변경/정면 맞추기 때만 다시 배치합니다. 한 번 선택 후 시선을 떼어야 다시 선택됩니다. VR 텍스트 필드는 시선으로 데모 대체 문구를 넣고, PC/박스 밖에서는 실제 키보드를 사용합니다.
