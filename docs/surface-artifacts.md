# 이동 중 면 깨짐 수정

2026-11-08 (Asia/Seoul). 사용자 Safari 스크린샷을 기준으로 검토했습니다.

## 확인한 원인

- 창틀 상·하단과 크림 벽은 두께가 모두 0.22m이고 중심 깊이도 같았습니다. 일부 영역에서 두 표면이 정확히 겹쳐 카메라를 움직일 때 표시 우선순위가 흔들릴 수 있는 구조였습니다.
- 충돌용 바닥의 연결을 위해 겹치게 만든 영역을 실제 바닥판으로도 그대로 그렸습니다. 네 모서리에 같은 높이의 중복 상면이 있었습니다.
- 밝은 수조 벽과 가느다란 창틀에 나타날 수 있는 그림자 자기 간섭도 보정했습니다. 이 항목은 스크린샷만으로 단독 원인을 확정하지 않았습니다.

## 수정

1. 창틀 상·하단의 두께는 0.30m, 세로 부재는 0.28m로 조정했습니다. 벽 표면보다 앞으로 돌출되어 같은 깊이의 면이 남지 않습니다.
2. 표시용 `floorSlabs`를 따로 두어 바닥판의 상면은 맞닿기만 합니다. 충돌용 `floorAreas`는 유지해 모서리 보행의 연속성을 보존했습니다. 수조 내부 바닥 구멍은 그대로입니다.
3. 회전된 출입구 간판도 글자 뒤에 받침판이 오도록 방향 계산을 수정했습니다.
4. 그림자는 2048×2048, normalBias 0.035 / bias -0.0004로 보정했습니다. 기존처럼 상태 변화 시 갱신하며 매 프레임 다시 생성하지 않습니다.
5. 낚시터의 클리핑 범위는 near 0.1m / far 60m로 좁혔습니다. 다른 월드는 기본값을 유지합니다. 깊이 정밀도 보완이며, 겹친 면을 그대로 두는 우회책으로 사용하지 않았습니다.

수정 파일: `architecture.ts`, `layout.ts`, `config.ts`, `src/engine/world/createWorld.ts`, `src/engine/rendering/Renderer.ts`, `profile.ts`. 회귀 검사는 `tests/surfaces.test.ts`입니다.

## 검증

`npm run check`의 린트, 14개 파일 83개 테스트, 기존 GLB 검증, 타입 검사, 프로덕션 빌드 및 개발 진단 분리를 통과했습니다. 실제 생성한 메시의 바닥판 AABB 사이에 면적 겹침이 없고, 총 바닥 면적이 15×11 − 8×4.5m²로 유지됨을 확인했습니다. 14개 창문의 앞/뒤 테두리가 벽보다 앞으로 나오는지, 두 간판의 글자가 받침판 앞에서 선택되는지도 검사했습니다.

브라우저와 Safari의 이동 중 시각 결과는 아직 재검수하지 못했습니다. 로컬 코드 변경 후 페이지를 새로고침하여 창틀과 수조 벽을 보며 좌우 이동해야 합니다. 개발 서버가 켜져 있다면 변경이 자동 반영되며, 예전 빌드의 preview 서버를 쓰고 있다면 다시 빌드 후 새로고침해야 합니다.
