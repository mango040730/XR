## 실행

현재 폴더에서:

```sh
npm ci
npm run dev -- --port 5173
```

이미 의존성이 있으면 `npm ci`는 생략합니다.

- 낚시터 바로 입장: `http://127.0.0.1:5173/?fishing`
- 기존 서비스: `http://127.0.0.1:5173/` → 데모 로그인/온보딩 → 혼자 활동해요 → 서버 입장
- 기존 엔진 월드 선택: `http://127.0.0.1:5173/?lab=1` → 고요낚시 선택
- 빌드: `npm run build`
- 빌드 결과 실행: `npm run preview -- --port 5173`

WebXR은 지원 기기와 보안 컨텍스트가 필요합니다. 원격 헤드셋의 일반 HTTP LAN 주소에서는 활성화되지 않을 수 있습니다. 이번 작업에서 인증서나 외부 배포를 설정하지 않았습니다.

| 동작 | 데스크톱 | 몰입형 VR |
| --- | --- | --- |
| 둘러보기 | 화면 클릭 후 마우스, Esc 해제 | 헤드셋 추적 |
| 이동 | WASD, 모바일 방향 패드·드래그 | 왼쪽 스틱 앞으로 유지 후 놓기: 바닥 텔레포트 |

| 투입·회수 | 낚싯대 클릭, F 또는 하단 버튼 | 낚싯대 또는 눈앞 초록 패널의 투입·회수 선택 |

빈 의자에 3m 이내로 접근해야 앉을 수 있습니다. 사용 중인 샘플 자리는 선택되지 않습니다. 안내의 샘플 인물을 끄면 12석 모두 사용할 수 있습니다. 샘플을 다시 켤 때 겹치는 자리에 앉아 있으면 안전한 통로로 먼저 일어납니다.

안내의 **전체 구도 보기**는 검수용 높은 시점(2.5m), **반대편 보기**는 반대 통로의 사람 눈높이(1.65m)입니다. 기본 입장 눈높이는 1.65m이며 착석은 1.12m입니다. VR에서 검수 카메라 전환은 비활성화됩니다.

## 구현

- 15×11m 실내, 낮은 천장 약 3.5m/용마루 4.65m, 수조 안쪽 8×4.5m, 수조 테두리 0.57m, 수면 약 0.385m, 바닥 약 -1.13m.
- 실내 바닥은 수조를 둘러싼 4개 영역입니다. 물 아래를 가로지르는 실내 바닥 평면은 없습니다. 수조 내부 벽과 바닥이 따로 존재합니다.
- 12석, 샘플 아바타 5명, 나무 의자·프레임 창문·지붕 보·사각 매달림 등·선반·도구함·거치대·뜰채·창밖 입체 나무. 배경은 저녁 하늘 단색이고 참고 이미지를 공간 평면/스카이박스로 사용하지 않았습니다.
- 메시/재질은 월드 내부에서 공유합니다. 정적 건축은 재질별 병합, 의자와 인물은 개별 객체 내 재질별 병합으로 렌더 호출을 줄였습니다. 움직이는 낚싯대·찌·파문은 분리했습니다.
- 조명은 기존 반구광·방향광과 따뜻한 점광원 2개입니다. 등은 발광 재질입니다. 실시간 그림자·반사·굴절·후처리 없이 낮은 비용의 접지 음영을 사용합니다.
- 물은 24×14 분할의 작은 높이 변화, 투명 청록 재질, 찌 부근 링 2개, 물고기 6마리의 느린 이동입니다. 가벼운 품질은 수면 버텍스 애니메이션을 생략합니다.
- 착석 시 가상 보행·일반 텔레포트는 중지합니다. 머리 추적은 유지합니다. 이미 실제로 앉은 사용자는 추가 높이 오프셋을 주지 않으며, 서 있는 사용자는 최초 착석 시 한 번만 오프셋을 정합니다. 실제 머리 움직임을 벽 충돌로 강제로 되돌리지 않습니다. 가상 이동은 계속 충돌 검사합니다.
- 사용자 ID, 위치·방향, 좌석 ID, 점유, 낚시 상태가 분리되어 있습니다. `sample:*` 소유자는 시연용 NPC이며 실제 접속자로 표시하지 않습니다.
- 장비 선택은 `InteractionSystem.actions`를 거쳐 데스크톱과 컨트롤러가 같은 명령을 사용합니다. 숨긴 인물·패널은 선택/가림 검사에서 제외합니다. 월드 전환·퇴장·서비스 취소 시 좌석 및 낚시 상태를 정리합니다.

## 이번 작업의 실제 검증과 제한

`npm run check`에서 린트, **12개 파일 74개 테스트**, 기존 GLB 검증, 타입 검사, 프로덕션 빌드와 개발 진단 제거 검사를 통과했습니다. Node v26.13.0 / macOS 환경입니다. GLB 검증의 오류·경고는 각각 0개이며, 낚시터는 코드로 생성한 메시여서 이 GLB 검증 수치의 대상은 기존 테스트 모델입니다.

추가 6개 테스트는 좌석 고유성·안전한 입장/통로 좌표, 수조/벽/가구 충돌·텔레포트 거부, 점유/자리 변경/투입/회수 정리, XR 착석 높이/머리 추적, 실제 Three.js 메시를 향한 레이 선택으로 착석→투입→회수→일어나기, geometry/material dispose를 검사합니다. Canvas는 Node 테스트에서 글자 그리기 경계만 대체했습니다. 실제 GPU 렌더링·브라우저 입력·실기기 확인으로 보고하지 않습니다.

개발 서버는 `127.0.0.1:5173`에서 시작했습니다. 직접 브라우저 연결은 사용할 수 없었고 컴퓨터 제어 권한도 부여되지 않았습니다. `npm run test:e2e`는 처음에 서버 소켓 제한(EPERM)으로 실패했고, 브라우저 테스트를 위한 확장 실행은 승인되지 않았습니다. 따라서 **이번 낚시터의 브라우저 실행, 시각 검수, 스크린샷 3종, 실제 프레임 속도/렌더 호출/GPU 성능은 미검증**입니다. 기존 문서의 과거 브라우저 성공 기록은 이 변경의 검증 결과가 아닙니다.

헤드셋을 사용하지 않았으므로 실제 WebXR 권한, 헤드셋·컨트롤러 추적, 텔레포트·스냅 회전·착석 편안함, 세션 종료 복구, 기기 FPS/발열은 **실기기 미검증**입니다. 지원 API와 기존 XR 입력 경로를 연결한 구현과 합성 pose를 사용하는 단위 검사를 구분합니다. 실제 멀티플레이, 정교한 물리/물고기 AI, 재화/상점/랭킹은 없습니다. Three.js 번들 크기 500KB 초과 경고는 유지됩니다.
